# n8n and Zapier commissioning gate — 2026-10-09

Owner: VAOS provider-control plane. Business authority: VYNDI OS. This document is a commissioning contract, not evidence of operational activation.

## Existing evidence
- Wave 3 n8n ephemeral CI qualification: PR #87; synthetic environment only.
- Wave 4 Zapier readiness contracts: PR #91; no production credential or live action.
- The automation fabric was introduced through PR #30, defaulting to disabled/evaluation provider manifests.
- The Infisical watchdog can be triggered manually or through a push, but repeated *unattended scheduled* success is not established. Infisical routing must remain disabled until independently verified.
- Windmill production routing remains disabled pending live cancellation, concurrency and timeout recovery evidence.

## Non-negotiable boundaries
1. VAOS is the sole authority for provider routing, approved scopes, kill switches, and audit; VYNDI OS remains the business system of record.
2. n8n and Zapier remain `enabled=false` and `evaluation` until separately approved; neither may activate Windmill or Infisical.
3. No local server or production credential in the repository. Use hosted endpoints / scoped secrets, if and when supplied. Do not silently create paid resources.
4. No provider-side business commitment from an AI recommendation without existing maker/checker and signed authority.
5. Outbound actions require idempotency key, short timeout, allowlisted destination, bounded request schema and no blind replay on ambiguous POST outcomes.
6. Callbacks require verification, correlation ID, replay protection, redaction and audit evidence before acknowledgment.
7. Independent verifier must cross-check VAOS intent, provider execution, callback outcome and VYNDI OS post-state.
8. Emergency disable must work without reliance on the disabled provider.

## n8n acceptance gates
- [ ] Identify an existing hosted n8n instance or explicitly authorize hosting; HTTPS endpoint, verified tenant, account owner.
- [ ] Scope an n8n credential to a single synthetic workflow; store outside GitHub code.
- [ ] Validate endpoint TLS, health, API rights and callback verification with a harmless test.
- [ ] Exercise success / 401 / 403 / timeout / duplicate callback / duplicate execution / unknown outcome.
- [ ] Verify kill switch while in flight and reconcile audit.
- [ ] Approve bounded provider qualification and routing, with rollback demonstrated.

## Zapier acceptance gates
- [ ] Establish workspace ownership, authentication method and allowed trigger/action capabilities.
- [ ] Verify one synthetic Zap/webhook without touching business records.
- [ ] Validate duplicate events, signature/authentication boundary, timeout, rate limit and replay behavior.
- [ ] Verify independent audit readback and revoke/disable path.
- [ ] Approve bounded provider qualification and routing, with rollback demonstrated.

## Promotion rule
Do not mark either provider ACTIVE based on implementation or CI tests alone. Require real provider run IDs, authenticated independent readback, captured PASS evidence and explicit scoped activation decision. Windmill remains OFF through both qualification workstreams.
