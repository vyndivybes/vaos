# JARVIS X review disagreement foundation

The founder-only JARVIS advisory now includes `reviewReconciliation`, built from the existing model candidate and deterministic evidence checker. A rejected proposal retains the fact that a model proposal was observed, the checker's veto and enumerated findings. The response displays a safe review explanation without repeating rejected model prose. Missing source domains remain visible even when bounded checks pass.

The current reviewers are a model proposer and a deterministic rule checker. They are not two independently qualified employee agents. `qualifiedAgentConsensus=false` and `independentAgentReviewsObserved=0` remain explicit. Requirement 13 therefore has a foundation, not full acceptance.

## Admission and behavior

The server records whether a draft passed admission before the deterministic review. An invalid output or provider failure does not become an admitted proposal or manufacture disagreement. A bounded consistency pass never certifies causation, source completeness, source versions, engineering release or production forecasting. Unknown/inconsistent metadata produces a review contract HOLD.

Findings are allowlisted codes from the existing checker; ordering is deterministic. No reviewer ID, raw model text, private ledger identifier, question body or extra payload is added to the reconciliation record. A query parameter cannot supply a verdict. Votes cannot override a safety veto. The existing authenticated GET, three-source bound, model-call quota and read-only permissions remain authoritative.

## Retention and next acceptance

Records live in the current response only; durable minority-opinion retention is not implemented by this increment. Full consensus and dissent acceptance still requires authenticated qualified reviewer identities, independent evidence-bound opinions, immutable retention and live multi-employee workflow verification. No new agents, database writes, migration, namespace, paid service or model call is introduced.

Regression coverage verifies model/checker disagreement, unavailable candidate/budget, source HOLDs, invalid metadata, safe summaries, deterministic findings and unchanged authority boundaries.
