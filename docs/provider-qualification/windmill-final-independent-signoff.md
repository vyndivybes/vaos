## Safe controlled cancellation drill specification

1. Create a harmless, bounded script `f/vaos/qualification_hold` whose sole
   effect is waiting 30–45 seconds and returning an innocuous marker. It MUST
   have no external API calls, filesystem writes, business side effects, or
   production workload access. A rapidly completing ping cannot qualify
   cancellation.
2. Provision three distinct, least-privilege identities where supported:
   **dispatch only** for `qualification_hold`, **cancel** restricted to the
   qualification job(s), and **read-only** for its job records. Check the
   actual available Windmill role/token permissions at commissioning; do not
   assume that script-path-based cancellation is inherently supported.
   No token may be printed into chats, code, logs or artifacts.
3. Before dispatch, durably reserve a sandbox slot with max concurrency 1,
   queued 0, expiry <= 60 seconds, kill switch available, and a distinct
   approval. No automatic second POST after an uncertain outcome.
4. Require an independent GET to prove the exact job is **running** before
   cancellation, send precisely one non-forced cancellation POST, then perform
   a separate read-only GET until `canceled:true` and `success:false`.
5. Do not release admission based solely on HTTP 2xx from cancel. Bind the
   final evidence to exact provider job ID, script path, source SHA, separate
   verifier run ID and immutable provider completion record.
6. If cancellation fails or readback becomes ambiguous, mark **HOLD** and
   preserve quarantine. Never attempt to cancel an unidentified business job.

## Real restart/eviction recovery specification

Use a **distinct isolated Cloudflare Durable Object identity**, never the
production admission object. Persist a live reservation and its fencing
epoch, then prove a genuine instance termination and replacement (e.g. with
instance-generation identity observed on either side of a controlled Worker
version transition, with Cloudflare deployment IDs). Afterwards, independently
check the identical Durable Object retains its reservation, epoch and audit
record, refuses a competing job and does not dispatch anything. A second HTTP
request without evidence of a new instance is **not** sufficient.

## Independent sign-off criteria

- Cancellation and restart evidence are generated by two separately
  identifiable execution runs and verified by a distinct auditor.
- GitHub source metadata, Cloudflare deployment, provider job terminal state,
  role separation and audit sequence are corroborated without trusting
  executor-generated PASS flags alone.
- The final assessment `READY_FOR_HUMAN_APPROVAL` still has
  `productionAuthorization:false`. Actual production enabling requires a
  separate owner-authorized change; never enable on assessment alone.

## Controlled live workflow

Deploy the bounded source in `integrations/windmill/qualification_hold.ts` to
`f/vaos/qualification_hold`. Reviewed Windmill version: `92dd4d9b9bff2d1d`.
Three distinct GitHub Actions secrets are required for this test only:
`WINDMILL_HOLD_DISPATCH_TOKEN`, `WINDMILL_HOLD_CANCEL_TOKEN`, and
`WINDMILL_HOLD_READ_TOKEN`, with respectively `jobs:run:scripts`,
`jobs:cancel`, and `jobs:read` scoped to that exact path. The owner approved
Windmill's 15-minute UI minimum; generate them immediately before execution.
Run **Windmill Controlled Cancellation** on main with `RUN_ONE_CANCELLATION`.
It reserves the global isolated DO slot before exactly one dispatch and requires
actual running readback before one non-force cancel. Expiry or uncertain
outcome leaves the slot occupied. `WINDMILL_CANCELLATION_KILL_SWITCH=true`
stops further test mutations without preventing readback or verified release.
Then run **Windmill Independent Final Audit**, supplying the successful
cancellation run ID and the separate eviction run ID. The auditor uses only
a read token and checks the provider's immutable completion record, exact
script version, source commits, and distinct run provenance. No workflow
activates production routing.
