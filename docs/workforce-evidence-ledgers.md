# Founder workforce evidence increment

Acceptance contract: protect and project independently reviewed departmental results, approved planning baselines versus independent completion, reviewed forecast intervals, CAPA retest/closure history, and employee report provenance. No production write authorization changes, seeded results, autonomous dispatch or certification.

The migration adds four empty append-only tables in `vaos_private`. RLS is enabled without policies. Public, browser and runtime service roles have no table privileges. The existing founder/server-key gated read RPC remains the only projection. No new writer endpoint is commissioned. Evidence registration requires an existing authorized database administrator and a separately reviewed evidence packet. This increment does not grant an employee permission to register, approve or certify its own evidence.

Department reviews require an in-scope route, authenticated environment, deployed version, canonical source, hashed evidence references, check evidence, independent reviewer, findings, corrective owner when findings exist, next due date and rationale. PASS requires all required checks and zero findings. Reviews remain historical observations of a route. They do not qualify an employee or authorize physical release. Superseding reviews reference earlier records; old rows cannot be edited or deleted. Evidence references and recorded hashes are provenance, not proof that this dashboard independently fetched or audited the artifact contents.

Planning records require approval evidence and explicit dates. SLA hours and mutable update timestamps are not planning baselines. The 30-day comparison uses the same approved work-package cohort for both series and independent, current-version handoff proof for actual completion. History older than 90 days is held, rather than counted as incomplete or overdue. Qualification drills are excluded from operational planning and reporting. Coverage refers only to the approved cohort, not the whole workload.

Forecast intervals are externally reviewed model outputs, not a newly trained model or automatic qualification. Require at least 20 samples, backtest coverage meeting the declared confidence, capacity, model version, independent reviewer, evidence, expiry and approved baseline IDs. `forecastInputSha256` hashes canonical baseline inputs and the current operational work snapshot. Any changed cohort, changed workload hash, incomplete snapshot, expiry or past prediction keeps the forecast on hold. Administrators must validate artifacts and model suitability before registering a qualification; this dashboard does not perform that certification.

CAPA evidence is separate from the existing mutable CAPA status. A closure event needs a prior passing retest on the same case and cannot reuse a retest superseded by failure or reopening. All event inserts lock the parent case. An event never changes the original CAPA status or pretends the partial register covers all departmental defects.

Employee reports project authored handoff evidence with current-version independent verification, action/owner matching, timestamp and report hash. The founder sees report identifiers and provenance, not an invented employee reply. External delivery, notifications, agent inbox processing and autonomous replies remain uncommissioned.

Verification includes negative evidence tests, executable isolated PostgreSQL migration/trigger/access tests, API founder authentication tests, repository suites, syntax checks, Worker dry-run, CI at the exact PR head and post-migration readback. Production migration and deployment require these gates. No fixture rows may be installed into production. Authenticated live UI acceptance must be reported separately if a valid founder session is unavailable.
